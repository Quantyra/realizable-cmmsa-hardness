S3152/S3154/S3156/E003. The reviewed 12a58220884586e42149acc6844821b64ff07536 integration had endpoint provenance and replacement bucket defects. This repair changes the production contract; old gates and historical observations cannot authorize it. Live eligibility remains HOLD. No live cloud operation was performed for this repair.

Production S3 and STS endpoints are fixed to us-east-1 in partition aws; IAM uses its official global endpoint with us-east-1 signing. Every constructor supplies ignore_configured_endpoint_urls=True, explicit endpoint_url and verify=True. S3 virtual addressing is explicit. Construction, cached client reuse and every signed request validate endpoint, region, partition, TLS verification and SigV4 scope. Mutation retry protections remain. Explicit fake HTTP transports remain available in synthetic tests. No alternate production endpoint option is exposed.

Read-only observations now require a paginated, prefix/region-filtered ListBuckets creation marker with canonical owner and region, captured in configuration and rechecked at closing. Missing, duplicate, ownerless, malformed, wrong-region or drifting markers reject. ListAllMyBuckets permission is therefore additionally required; an access denial fails closed. Historical receipts lacking the marker are preserved as historical evidence.

A new mandatory production proof named bucket_continuity has type archive-root-reviewed-bucket-continuity-v1. The producer-quiescence Root acceptance must bind it. It contains exact packet/allowlist/full205 rows, Root ACCEPT/role/TTL/custodians, prefreeze_marker, postfreeze_marker, and committed pointers prefreeze_observation, postfreeze_observation (the accepted baseline), freeze_journal, creator_shutdown_receipt and name_guard_receipt. Each extra receipt must be present in committed underlying Root acceptance. The complete prefreeze and postfreeze namespaces cover the exact original205 mappings, and metadata is unchanged.

The separately accepted archive-actual-freeze-transition-journal-v1 binds the actual PutBucketPolicy operation, pinned cyint-ea principal, request/readback IDs, policy hash, pre/post markers, pre/post configuration hashes, allowlist/full205 rows, chronology and an independently reviewed no-delete-or-recreate observation. Both identical markers and a policy-induced marker change require this journal. Marker changes are never adopted from current cloud state. The creator shutdown and name guard receipts require actual operating commands, Root review, effective observations before the prefreeze observation, custodians and leases through gate expiry. These receipts do not create controls; Root must substantively verify their truth and coverage.

Current marker equality is checked whenever the production source/destination namespaces are read, before the first empty bucket intent, after SDK signing immediately before the physical mutation send, and during closing/reconciliation. Bucket intent retains its accepted marker. Source absence must agree between owned S3 NoSuchBucket and a fresh ListBuckets observation. Physical bucket send additionally requires an empty complete versions/markers/uploads namespace. A changed marker or bucket reappearance fails without a resend or terminal success. Durable intent is retained on ambiguity.

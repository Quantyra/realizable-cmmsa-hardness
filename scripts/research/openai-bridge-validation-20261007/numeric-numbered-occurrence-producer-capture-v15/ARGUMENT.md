# Numbered occurrence producer: concrete row-serialization increment

This v13 successor preserves the semantic numbered producer, output validator, parser bounds, degree and overlap transfers, violation-count identity, variable bound, fixed legal malformed-input fallback, and exact upstream unary format. It keeps v12's explicit owner, cloud-dart, and tag-generation transitions, repairs the family Cobham lift to the one-coordinate vector API, and adds explicit original-row and equality-gadget row serialization from the generated tags. The source remains uncompiled and unaccepted.

The main `State` has eighteen independently framed fields: phase; unread bits; unary count; decoded words; slot cursor and ordered source-slot trace; owner and owner-scan cursors; owner sizes, current occurrence accumulator, and completed owner occurrence lists; port occurrence and port-label cursors; variable tags; current cloud representatives and completed representative clouds; and edge/internal-label cursors. The independent length prefixes give fixed field boundaries while values vary. `TagLookupState` separately stores the ordered tag vector, requested tag, cursor, result, and completion bit; each lookup transition examines one current tag and advances by at most one.

The parser consumes one bit per step and appends a numeral only on a false delimiter. Once its exact parser accepts the input, the slot scanner walks the input's original rows and three coordinates in row-major order and records `(row, coordinate, owner)`, preserving duplicate rows and repeated variable names. For each owner in increasing order, the next scan walks that slot trace and retains exactly entries with the current owner. Their stored indices are `3*row+coordinate`, in the exact filtered source order; the list length is the owner's cloud size. The port phase then emits tags `(0, owner, occurrence ordinal, local port)` in occurrence-major and port-major order.

For that same owner, the cloud-dart phase scans the literal product order `Fin n × Fin D × Fin 3` using cursor decomposition `d=cursor%3`, `q=cursor/3`, `v=q/D`, and `j=q%D`. The numeric rank is `j+D*v`, matching the pinned `finProdFinEquiv` ordering. External darts call the fixed `Complexity.algBase.famRotFn (2X)` string program; forward/backward cycle darts use the explicit modular successor/predecessor. The transition retains a dart exactly when its source rank is strictly below the returned reverse endpoint's rank. That preserves parallel dart orbits and drops loops. At size zero the loop has zero iterations and makes no family call. For each retained representative, the internal-tag phase emits `(1, owner, edge ordinal, t)` for `t=0..4`, then advances to the next owner. Thus generated tags use the actual per-owner order: all occurrence-port variables followed by representative-edge internal variables.

The fixed-family `FP` witness is `Complexity.FinBase.famRotFn_mem_FP` at `2X`. `familyRotationProgramVec_mem_Cobham` applies the pinned `Complexity.FP_subset_CobhamFP` to the explicit one-coordinate lift `familyRotationProgram (x 0)`. The exact call equality is `famRotFn_eq`; its fit-level premise is discharged using the pinned `fitLevel_le`, because `fitLevel n ≤ 2n = eval (2X) n`. The `familyRotationValue` helper extracts the unary pair's two numeral lengths and proves equality to the library `famRotVal` for positive cloud size. This certifies the fixed family subroutine only, not the containing phase machine or its global iteration.

The added serializer uses `slotTrace` to recover a source slot's owner, searches that owner's recorded prefix list for the slot ordinal, then searches the ordered tag vector for `(0, owner, occurrence, 0)`. This is the exact `ActualOccurrenceAllocation.anchor` rule: every original row coordinate uses port zero, and repeated owners still get distinct slot ordinals. Gadget rows use the pinned fixed four-row table `[(0,2,3),(1,4,5),(2,4,6),(3,5,6)]`; table labels 0 and 1 select the representative dart's source/target port tags, while 2 through 6 select that edge occurrence's five internal tags. Each of the four gadget right-hand sides is zero. The serializer builds original rows first, then representative clouds in owner order and gadget rows in table order, and emits `encodeWords ([V,M] ++ row fields)` in the exact unary wire format. Missing tag lookup fails closed; invalid parser state emits the fixed legal fallback.
